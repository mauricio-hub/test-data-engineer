# S02: privacidad de clientes y validación local

`make clients` ejecuta solo la carga de clientes. `make run` sigue pendiente de S03/S04 y devuelve error explícito. PostgreSQL conserva el puerto host 55432 y el interno 5432. No se borran volúmenes ni se rotan contraseñas ya inicializadas.

## Qué protege

`data_classification.yaml` se comprueba contra las columnas reales antes de escribir. Todo texto del maestro se cifra; la vista `analytics.v_clientes` solo devuelve `cliente_id`. Las observaciones se enmascaran antes de cifrar. Correos, celulares colombianos y documentos se detectan con reglas conservadoras; no se promete detección universal. El contador cuenta clientes, no coincidencias.

Fernet añade autenticación al cifrado. El contenido también vincula el valor al cliente y columna: cambiarlo de lugar produce error al verificar. La llave no llega a PostgreSQL, logs ni manifiesto. Si ya hay clientes, se verifica la llave contra un registro antes de escribir; no cambiarla sin una migración explícita.

CSV inválido o identificadores inválidos/repetidos rechazan el archivo completo, sin carga parcial. La cuarentena conserva sus bytes cifrados, motivo y hash; `record_number=0` indica archivo completo. Los conteos desconocidos de un archivo rechazado se registran como cero, no como estimaciones. Un fallo SQL revierte toda la carga y produce un mensaje genérico, sin la excepción del driver.

## Configurar la llave en PowerShell

Primero ejecutar `make setup`. Si ya tienes una llave Fernet válida y protegida fuera del repositorio, configura solo su ruta en `BIA_PII_KEY_FILE`. No ejecutes el bloque de creación sobre una llave que debas conservar.

Para crear **explícitamente** una llave nueva, sin imprimirla y sin sobrescribir otra:

```powershell
$secretDirectory = Join-Path $env:LOCALAPPDATA 'BiaEnergySecrets'
New-Item -ItemType Directory -Force $secretDirectory | Out-Null
$keyOwner = [System.Security.Principal.WindowsIdentity]::GetCurrent().Name
icacls $secretDirectory /inheritance:r /grant:r "${keyOwner}:(OI)(CI)F"
$env:BIA_PII_KEY_FILE = Join-Path $secretDirectory 'pii.fernet.key'
@'
import os
from cryptography.fernet import Fernet
with open(os.environ['BIA_PII_KEY_FILE'], 'xb') as handle:
    handle.write(Fernet.generate_key())
'@ | & .\.venv\Scripts\python.exe -
```

La variable contiene una ruta, no la llave. Verifica las ACL con `icacls $env:BIA_PII_KEY_FILE`; deben limitar acceso a tu cuenta y administradores autorizados. Conserva una copia segura fuera del repositorio y del ZIP: perderla impide recuperar lo cifrado. En POSIX se rechazan permisos de grupo/otros. En Windows la aplicación exige ubicación externa, pero la revisión de ACL corresponde al operador.

No se crea una llave durante setup, up, clients ni al faltar configuración. El proceso falla antes de leer el maestro o abrir la base si falta la llave.

## Validar S01 y S02

Desde la raíz, con Docker Desktop activo y la llave configurada:

```powershell
$env:PG_PORT = '55432'
$env:S01_PSQL = $null
$env:BIA_TEST_DB_DRIVER = $null
make up
if ($LASTEXITCODE -ne 0) { throw 'No continuar: falló make up' }
$composeArgs = @('--project-name','bia-evaluation','--env-file','.local/compose.env','-f','docker-compose.yml')
docker compose @composeArgs ps
$redpandaContainer = docker compose @composeArgs ps -q redpanda
docker inspect --format '{{json .State.Health}}' $redpandaContainer
docker compose @composeArgs exec -T redpanda rpk cluster health -X admin.hosts=127.0.0.1:9644
docker compose @composeArgs exec -T postgres pg_isready -h 127.0.0.1 -p 5432 -U postgres -d bia_datos
Test-NetConnection 127.0.0.1 -Port 55432 -InformationLevel Quiet
make test
if ($LASTEXITCODE -ne 0) { throw 'No continuar: fallaron las pruebas' }
make clients
```

El cambio de Compose requiere recrear el contenedor, no basta con reiniciarlo: `make up` aplica esa actualización conservando el volumen. El nuevo healthcheck consulta la API administrativa 9644 una vez; Docker repite la comprobación. Se retiraron `--brokers` (Kafka) y el modo de espera. Fuentes de la versión fijada: [health.go](https://github.com/redpanda-data/redpanda/blob/v26.2.2/src/go/rpk/pkg/cli/cluster/health.go) y [opciones administrativas](https://github.com/redpanda-data/redpanda/blob/v26.2.2/src/go/rpk/pkg/config/params.go). Sin acceso al motor no puede confirmarse que sea la única causa del contenedor existente.

Sin GNU Make, los equivalentes son `.\.venv\Scripts\python.exe tools/manage.py prepare`, luego `... tools/manage.py up`, `... -m unittest discover -s tests -v` y `... -m src.clients`. No utilizar `S01_PSQL` para apuntar a otro proyecto.
